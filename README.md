# 酒馆红笔标记 0.1.6

在酒馆聊天正文中选字、标记，让已保存的原文持续参与后续对话。包含完整源码，不需要构建，也不需要酒馆助手。

这是可安装的开发测试版，兼容酒馆 **1.18.0 / 1.19.0** 的已核对接口。已在隔离的真实 1.18.0 中检查加载、标记、原生生成请求、分支及刷新恢复；模型使用本地模拟接口。真实安卓、真实模型服务及完整产品验收仍待执行。逐项状态见 [验收记录](docs/ACCEPTANCE.md)。

## 安装

在酒馆的扩展管理器中点击“安装扩展”，粘贴仓库地址：

```text
https://github.com/cjhkcjgk3-sys/sillytavern-red-pen
```

安装后刷新酒馆，点击输入框左下角的 **魔术棒 → 红笔标记**。所有常规操作都集中在同一面板，页面不再放置右下角悬浮按钮。首次使用默认暂停，在面板中点击“开启标记”。

已经安装旧版时，在扩展管理器中更新“红笔标记”后刷新页面，确认面板版本为 **0.1.6**。本次更新保留已有标记与编号；手动安装时覆盖插件文件，不清理浏览器网站数据。

也可以下载源码或安装包后手动安装：

1. 解压安装包，将整个 `red-pen` 文件夹放到酒馆根目录的 `data/<你的用户目录>/extensions/red-pen/`。默认账号通常是 `data/default-user/extensions/red-pen/`。
2. 确认路径下直接有 `manifest.json`、`index.js`、`style.css` 和 `src/`，避免多套一层目录。
3. 刷新酒馆，在扩展管理中确认“红笔标记”已启用，然后从左下角魔术棒打开“红笔标记”。

也可以安装到 `public/scripts/extensions/third-party/red-pen/` 供全部账号加载。同一份插件选择一种安装位置。扩展管理器的“通过 URL 安装”使用上面的 Git 仓库地址；本地 ZIP 采用文件安装。GitHub 自动下载的源码目录通常叫 `sillytavern-red-pen-main`，可将该目录重命名为 `red-pen` 后按上述路径放置。

兼容基准为 **SillyTavern 1.18.0** 正式标签及 **1.19.0** 的指定源码快照，启动时检查必需能力。1.18.0 已做隔离实例测试，1.19.0 已核对源码并保留回归测试；其他补丁、分支及修改版需另验。建议先在备份后的聊天中试用。标记优先使用浏览器原生 CSS 文字高亮；浏览器没有此能力时自动改用叠加层画红笔，功能不降级，面板“状态检查”会显示当前使用的方式。Safari、Firefox 和真实安卓 / iOS 设备未测。

0.1.3 起 `minimum_client_version` 降到 **1.12.0**：更老的酒馆也能装上并看到面板与诊断；低于 1.18 时面板会提示“未验证”，只按基础标记使用。同时移除了对 `structuredClone`、`Array.at`、`findLast`、`Object.hasOwn` 的强依赖，照顾旧安卓浏览器内核。

## 使用

1. 进入一段聊天，点击 **左下角魔术棒 → 红笔标记 → 开启标记**，关闭面板回到聊天。
2. **手机：系统长按普通聊天正文 → 拖动原生选区手柄 → 轻触选区操作中的“标记”。** 想再少一步，可在面板里勾选 **“选中即标记”** 并把延迟改成 0.5–30 秒（默认 1 秒）：选好字等一会儿自动保存，不用点浮条；选字复制时也会标记，提示条上有「撤销」。 长按负责选字，不会自动保存；还需点击一次“标记”。桌面用鼠标拖选，再点附近的“标记”。系统复制菜单继续保留，选区入口也提供复制。图片、视频及角色卡内嵌网页暂不支持。
3. 在不同消息中继续标记。正文出现红色底纹与下划线，摘录自动进入当前聊天的标记库。
4. 直接发要求，例如“标记 1 原文保留，标记 3 改写”。标记本身不预设保留、删除或改写。

轻触已有红色标记会直接弹出“取消标记”，再点一下就取消（两步），也可从库中取消。**选中一段已经标过的文字时，浮条上会直接出现「取消标记（N）」**，点一下即可；**把选区扩大到原来的标记之外再标记，会合并成一条并保留原编号**，不会再报“范围重叠”。取消后有 10 秒撤销入口，恢复原编号。

从 **魔术棒 → 红笔标记 → 打开标记库** 管理摘录。标记库支持原文搜索、展开全文、复制、返回来源、勾选批量取消。勾选只影响管理；搜索和勾选都不改变发送范围。搜索变化会清空勾选。备份、恢复和附加内容核对在“更多”里。

在同一控制面板点击 **暂停标记**，即可隐藏红线和新增入口，并停止为之后的请求附加材料；不用在扩展管理器中停用整个插件。内容库仍可查看与管理。在途请求保持启动时的快照。编号不会因取消、搜索或排序而重排。

## 看不到入口或长按没反应

先确认已经更新到 0.1.6 并刷新了酒馆页面，再检查左下角魔术棒中是否有“红笔标记”。面板里的“状态检查”会显示插件版本、启动失败原因及浏览器能力。核心文件加载或启动检查失败时，魔术棒入口仍保留，错误信息会持续显示；不再只弹一下提示就消失。可以先更新、刷新，再点击“重新检查启动”。

如果某条消息的显示内容在标记之后被改动（行号、重渲染、其他扩展改写 DOM），这条消息上的红线会暂时隐藏，插件会在聊天里提示一次，摘录仍完整保存在标记库中。关闭「前端代码块高亮」这类只改渲染、不改字符的开关不受影响。

如果长按选字后没有出现“标记”，先回到 **魔术棒 → 红笔标记**：面板里的“标记当前选中的文字”可以直接标记刚才的选区，“状态检查”会写明最近一次选区是没检测到、在正文外还是无法标记。触屏上也可以用面板里的开关确认当前是否真的处于“已开启”。

如果面板显示已暂停，需要先点“开启标记”。如果状态检查里“最近选区”一直显示“没有选区”，说明浏览器没有把长按选区交给页面，可改用面板里的“标记当前选中的文字”。如果显示“选区不在聊天正文内”，请确认选中的是普通聊天正文；面板打开时不会弹出“标记”，关闭面板即可。卡内网页中的文字与主页面选区属于不同范围。

## OpenAI 兼容与 Google Cloud

在酒馆原有的“聊天补全”连接中配置服务与密钥：

- OpenAI 或 OpenAI 兼容服务：沿用酒馆现有连接。
- Google 原生 Gemini 格式：沿用酒馆的 Google AI Studio / MakerSuite 连接。
- Google Cloud：沿用酒馆的 Vertex AI 连接。

插件在酒馆的格式转换之前附加材料，服务器继续负责转换成 `messages` 或 Google 的 `contents / parts` 并处理认证。插件不额外收集、保存或传输密钥。上述转换路径已做指定源码核对，真实服务调用未测。自定义代理需要先能在酒馆中正常对话。

覆盖普通发送、重新生成、继续生成和切换生成新回答；自动标题、摘要等 `quiet` 请求不附加。其他扩展通过原生正常生成流程调用时走同一路径；独立后台生成、并发生成和自行发送到其他地址的扩展未支持。文本补全连接不在本版支持范围，开启且库非空时会暂停对应原生生成并提示切换连接。

## 保存、来源与容量

摘录保存在当前浏览器的 IndexedDB，按酒馆账号、角色或群组、聊天完整性标识隔离，必要时追加插件自己的独立标识。刷新、同一浏览器重新进入和插件文件更新继续使用原库。聊天重命名使用同一标识；原生分支按已继承消息及可确认回答版本复制记录，父子库独立。

酒馆 1.18 创建分支时可能复制父聊天的完整性标识。首次进入这类分支，插件会在聊天元数据中保存自己的隔离标识，保持酒馆原有的 `integrity` 和正文不变。标识保存失败时暂停该库并提示重试，不读取父库代替。已存在的 0.1.0 普通聊天库与已确认的 1.19 分支库继续使用原 key，无需清库或重做标记。

首次为聊天标记或恢复备份，会通过酒馆原生保存操作确认聊天标识已写入服务器；确认失败不添加记录。插件不改写消息正文。聊天库写入事务完成后才显示“已标记”。源消息被编辑、删除或切换回答时，旧摘录继续保存与发送，只有能够确认对应位置时才标红。无法唯一识别的消息拒绝新增；正文渲染变化时采取保守定位，不把标记迁移到相似文字。

备份文件可恢复到当前选中的聊天。跨聊天恢复作为独立副本，不自动标红；编号冲突会预览并汇报重新分配结果。备份含完整摘录，请按聊天资料保存。更换浏览器、清理网站数据、无痕窗口或系统回收网站存储后，需要用备份恢复；本版没有跨设备同步。

每次发送从当前库冻结完整快照，以中性说明与 JSON 材料数组追加一次；JSON 的 `text` 字段解码后就是完整摘录，保留原有换行与缩进。旧消息退出历史上下文不会删除这些材料。

最终请求会核对全文，并用酒馆分词器进行文字 Token 估算。已估算超出上下文容量时，在提交前暂停；不会截断或少发。多模态、工具及服务端额外开销无法完整判断，容量提示不会声称全部已确认。标记在历史构建完成后附加；长聊天接近上限时，需要减少酒馆的历史消息窗口、调整上下文或减少标记，再重试。不会自动删改历史请求内容为标记腾空间。

“查看本次附加内容”区分当前准备内容、最近捕获的实际提交材料及服务器返回状态。“服务器已接收”只描述酒馆服务器响应，模型是否成功执行以酒馆结果为准。服务拒绝和网络错误不会删除摘录。

## 开发与验证

```sh
npm ci
npm run check
npm test
npm run test:browser
```

浏览器检查使用系统 Chromium / Edge；可用 `CHROMIUM_PATH` 指定其可执行文件（Windows 示例：`CHROMIUM_PATH="C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" npm run test:browser`）。本地测试夹具会发出模拟请求，不使用密钥。运行时只有原生浏览器模块，没有 npm 或 CDN 运行依赖。

还有可选的真实 1.18 回归脚本 `tests/runtime-118.mjs`。仅在全新、可丢弃的数据目录中启动 1.18.0，并安装本插件，再运行：

```sh
RED_PEN_RUNTIME_TEST=isolated-1.18 ST_118_URL=http://127.0.0.1:8128 npm run test:runtime:118
```

此脚本会创建测试角色、聊天、分支和连接设置，使用本地 OpenAI / Google 模拟服务；不能指向日常使用的数据目录。它没有真实模型密钥，也不检验模型效果。

源码：`index.js` 负责魔术棒统一入口与持久启动诊断，按需加载 `src/app.js` 管理酒馆生命周期；`src/compat.js` 负责聊天隔离适配，`src/core.js` 负责记录与备份，`src/dom.js` 负责可见选区和高亮，`src/store.js` 负责事务保存，`src/transport.js` 负责请求核对，`src/ui.js` 负责标记库和选区界面。

兼容清单、逐项验收、证据和已知限制见 [ACCEPTANCE.md](docs/ACCEPTANCE.md)，API 依据见 [API-SOURCES.md](docs/API-SOURCES.md)。
