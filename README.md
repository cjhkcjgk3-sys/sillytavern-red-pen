# 酒馆红笔标记 0.1.0

在酒馆聊天正文中选字、标记，让已保存的原文持续参与后续对话。包含完整源码，不需要构建，也不需要酒馆助手。

这是可安装的开发测试版。已完成自动逻辑和本地浏览器夹具检查；真实酒馆、真实安卓及实际模型接口尚未验收。逐项状态见 [验收记录](docs/ACCEPTANCE.md)。

## 安装

在酒馆的扩展管理器中点击“安装扩展”，粘贴仓库地址：

```text
https://github.com/cjhkcjgk3-sys/sillytavern-red-pen
```

安装后刷新酒馆，确认“红笔标记”已启用。首次使用默认关闭，需要手动打开总开关。

也可以下载源码或安装包后手动安装：

1. 解压安装包，将整个 `red-pen` 文件夹放到酒馆根目录的 `data/<你的用户目录>/extensions/red-pen/`。默认账号通常是 `data/default-user/extensions/red-pen/`。
2. 确认路径下直接有 `manifest.json`、`index.js`、`style.css` 和 `src/`，避免多套一层目录。
3. 刷新酒馆，在扩展管理中确认“红笔标记”已启用。首次使用右下角显示“红笔：关闭”和“标记库”。

也可以安装到 `public/scripts/extensions/third-party/red-pen/` 供全部账号加载。同一份插件选择一种安装位置。扩展管理器的“通过 URL 安装”使用上面的 Git 仓库地址；本地 ZIP 采用文件安装。GitHub 自动下载的源码目录通常叫 `sillytavern-red-pen-main`，可将该目录重命名为 `red-pen` 后按上述路径放置。

开发基准为 **SillyTavern 1.19.0** 的指定源码快照，启动时会检查必需能力。建议先在备份后的聊天中试用。使用支持 CSS 文字高亮的新版 Chrome / Edge；不支持时会明确停止启动。Safari、Firefox、旧酒馆和第三方修改版未测。

## 使用

1. 进入一段聊天，点“红笔：关闭”切换为开启。
2. **手机：系统长按选字 → 拖动原生选区手柄 → 轻触浮动入口“标记”。** 桌面用鼠标拖选，再点附近的“标记”。系统复制菜单继续保留，浮动入口也提供复制。
3. 在不同消息中继续标记。正文出现红色底纹与下划线，摘录自动进入当前聊天的标记库。
4. 直接发要求，例如“标记 1 原文保留，标记 3 改写”。标记本身不预设保留、删除或改写。

轻触已有红色标记，再点“取消标记”；也可从库中取消。取消后有 10 秒撤销入口，恢复原编号。

标记库支持原文搜索、展开全文、复制、返回来源、勾选批量取消。勾选只影响管理；搜索和勾选都不改变发送范围。搜索变化会清空勾选。备份、恢复和附加内容核对在“更多”里。

关闭总开关后隐藏红线和新增入口，并停止为之后的请求附加材料；内容库仍可查看与管理。在途请求保持启动时的快照。编号不会因取消、搜索或排序而重排。

## OpenAI 兼容与 Google Cloud

在酒馆原有的“聊天补全”连接中配置服务与密钥：

- OpenAI 或 OpenAI 兼容服务：沿用酒馆现有连接。
- Google 原生 Gemini 格式：沿用酒馆的 Google AI Studio / MakerSuite 连接。
- Google Cloud：沿用酒馆的 Vertex AI 连接。

插件在酒馆的格式转换之前附加材料，服务器继续负责转换成 `messages` 或 Google 的 `contents / parts` 并处理认证。插件不额外收集、保存或传输密钥。上述转换路径已做指定源码核对，真实服务调用未测。自定义代理需要先能在酒馆中正常对话。

覆盖普通发送、重新生成、继续生成和切换生成新回答；自动标题、摘要等 `quiet` 请求不附加。其他扩展通过原生正常生成流程调用时走同一路径；独立后台生成、并发生成和自行发送到其他地址的扩展未支持。文本补全连接不在本版支持范围，开启且库非空时会暂停对应原生生成并提示切换连接。

## 保存、来源与容量

摘录保存在当前浏览器的 IndexedDB，按酒馆账号、角色或群组、聊天完整性标识隔离。刷新、同一浏览器重新进入和插件文件更新继续使用原库。聊天重命名使用同一标识；原生分支按已继承消息及可确认回答版本复制记录，父子库独立。

首次为聊天标记或恢复备份，会通过酒馆原生保存操作确认聊天标识已写入服务器；确认失败不添加记录。插件不改写消息正文。聊天库写入事务完成后才显示“已标记”。源消息被编辑、删除或切换回答时，旧摘录继续保存与发送，只有能够确认对应位置时才标红。无法唯一识别的消息拒绝新增；正文渲染变化时采取保守定位，不把标记迁移到相似文字。

备份文件可恢复到当前选中的聊天。跨聊天恢复作为独立副本，不自动标红；编号冲突会预览并汇报重新分配结果。备份含完整摘录，请按聊天资料保存。更换浏览器、清理网站数据、无痕窗口或系统回收网站存储后，需要用备份恢复；本版没有跨设备同步。

每次发送从当前库冻结完整快照，以中性说明与 JSON 材料数组追加一次；JSON 的 `text` 字段解码后就是完整摘录，保留原有换行与缩进。旧消息退出历史上下文不会删除这些材料。

最终请求会核对全文，并用酒馆分词器进行文字 Token 估算。已估算超出上下文容量时，在提交前暂停；不会截断或少发。多模态、工具及服务端额外开销无法完整判断，容量提示不会声称全部已确认。标记在历史构建完成后附加；长聊天接近上限时，需要减少酒馆的历史消息窗口、调整上下文或减少标记，再重试。不会自动删改历史请求内容为标记腾空间。

“查看本次附加内容”区分当前准备内容、最近捕获的实际提交材料及服务器返回状态。“服务器已接收”只描述酒馆服务器响应，模型是否成功执行以酒馆结果为准。服务拒绝和网络错误不会删除摘录。

## 开发与验证

```sh
npm ci
npm run check
npm test
npm run test:browser
```

浏览器检查使用系统 Chromium；可用 `CHROMIUM_PATH` 指定其可执行文件。本地测试夹具会发出模拟请求，不使用密钥。运行时只有原生浏览器模块，没有 npm 或 CDN 运行依赖。

源码：`index.js` 负责酒馆生命周期，`src/core.js` 负责记录与备份，`src/dom.js` 负责可见选区和高亮，`src/store.js` 负责事务保存，`src/transport.js` 负责请求核对，`src/ui.js` 负责界面。

兼容清单、逐项验收、证据和已知限制见 [ACCEPTANCE.md](docs/ACCEPTANCE.md)，API 依据见 [API-SOURCES.md](docs/API-SOURCES.md)。
