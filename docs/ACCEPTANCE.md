## 0.1.3：触屏长按选区不出“标记”入口

用户反馈：手机上插件显示已开启，长按正文选字（与长按复制是同一套系统选区）后没有任何反应，也没有“标记”入口。

复核代码后确认三条会让入口**静默消失**的路径，其中第一条已在本地 Chromium 夹具复现：

1. 入口快捷判定用 `selection.anchorNode.parentElement.closest('.mes_text')`。浏览器把选区锚点放在元素节点时（触屏长按、整段选择常见），`parentElement` 已经跳到 `.mes` 之外，于是直接判定“不在正文内”并隐藏入口，`captureSelection()` 本身能处理这种锚点却轮不到执行。修复：起点、终点分别按“元素节点或文字节点”解析。
2. 只监听 `selectionchange` / `pointerup`。部分安卓浏览器与内嵌 WebView 在长按选区时不派发 `selectionchange`。修复：增加 touchend / mouseup / contextmenu / keyup 触发，并在 touchstart / pointerdown 后 2.5 秒内轮询一次选区。
3. 缺少 CSS Custom Highlight 时整体暂停标记，界面上只剩面板里的说明。修复：改用 `pointer-events:none` 的叠加层绘制红笔，聊天 DOM 仍是只读。

同时补：控制面板“标记当前选中的文字”兜底入口；状态检查显示最近一次选区的判定（事件来源、是否在正文内、失败原因）；边界空白自动裁剪（起点已对齐时不裁剪，代码缩进保留）；操作失败改用插件提示条（`alert()` 会阻塞页面，已在夹具中复现卡死）；`npm run check` 在 Windows 下的路径分隔符修复。

已验证（本地，非安卓实机）：`npm test` 16/16；`npm run check` 在 Windows 通过；用内置 Chromium 打开 `tests/fixture.html` 手工复核——元素节点锚点显示入口（state=ok）、文本节点选区正常、跨消息选区给出中文提示、叠加层在可见消息上画出矩形、面板显示“标记当前选中的文字”与最近选区诊断。

未验证：真实安卓长按与系统选区手柄、iOS、`tests/browser.mjs`（本机未安装 playwright-core），以及 1.18 隔离实例复跑。

0.1.4 追加：投影指纹不一致时在聊天里提示一次（`reportPaintGap`，生成中不提示）。已用夹具验证两类场景——把同样的字符包进 `hljs` span（不影响）、按 StageDog「取消代码块高亮」脚本的做法把 `pre code` 的 innerHTML 重写为纯文本（不影响，重写后红线仍在）；人为插入行号等可见文字时才隐藏红线并提示。

版本门槛同时下调：`minimum_client_version` 1.18.0 → **1.12.0**。此前若酒馆低于 1.18，扩展管理器会直接拒绝加载，页面上连菜单和面板都没有；现在会加载并在面板显示实际版本与“未验证”提示。低版本只声明基础标记可用，日期/事件/请求格式差异没有实测；`preflight` 仍会在缺少必需接口时给出中文原因。

## 0.1.2：入口不可见问题与操作统一

用户反馈右下角两个按钮均不可见，并指定左下角魔术棒作为唯一常驻入口。已在真实隔离 1.18 中复现旧版的一条失败路径：模拟缺少 CSS 高亮能力时，0.1.1 会在 preflight 退出，页面没有操作条，也没有持续显示的诊断界面。尚未取得用户实际浏览器环境，因此没有将这条复现路径断言为用户设备的确切原因。

本版将入口独立在根模块：**魔术棒 → 红笔标记** 打开统一面板，开启 / 暂停 / 内容库集中管理。核心按需加载，加载失败仍保留入口和错误说明。缺少高亮时仍可查看已存内容库，新增与发送附加暂停。移除右下角常驻条；选字完成后仅临时显示选区操作入口。

回归证据：真实 1.18 通过原生魔术棒点击操作、手机宽度布局和故意阻断核心模块后的错误展示；浏览器夹具通过缺少高亮时的控制面板、禁用开启按钮、保留库内容，以及触屏选区后操作。真实 iOS / 安卓设备原生长按仍未测。

## 已知限制与需联测事项

1. 已适配指定 1.18.0 和 1.19.0，1.18 增加隔离真实运行证据。其他版本、修改版和用户自己的具体安装环境仍需另验。
2. 数据保存在当前浏览器账号的 IndexedDB，没有跨设备云同步。浏览器网站数据清理、无痕模式及系统回收需要备份恢复。
3. 原生主页面 DOM `.mes[mesid] .mes_text` 属于明确依赖。主题只改色彩通常可沿用；替换 DOM、隐藏正文、改写 `send_date` 或重组回答数组的扩展需要专项联测。无法确认时保留摘录并停止对应高亮。
4. 只支持同源原生聊天补全流程，独立或并发后台请求、文本补全、非标准端点以及 fetch 替换冲突未支持。不开额外 API 密钥设置。
5. 标记附加在宿主历史构建完成之后。不会自动挤掉历史；已估算容量不足需减少历史窗口、标记或调整配置再试。分词和多模态容量仍存在估算边界。
6. 返回来源要求该消息已加载到 DOM；如果酒馆尚未加载旧历史，会提示先向上加载历史。不会用相同文字的其他位置代替来源。
7. 不同消息分别标记；表格仅单元格内；图片、视频、iframe、复杂嵌入页面和非正文控件不支持。被选范围边界处空白不能准确映射时拒绝，不猜测。
8. 源码仓库为 `https://github.com/cjhkcjgk3-sys/sillytavern-red-pen`，支持扩展管理器使用仓库 URL 安装。源码公开不代表已经通过正式首版验收；没有执行用户生产环境安装或付费模型调用。
9. 备份完整性检查会拒绝损坏和缺字段文件；尚未设计更高版本备份迁移协议。本版不含多色、标签、逐条发送开关与跨聊天共享库。
